# Experimental N57 migration

This fork brings the factory-derived N57 catalog and xDrive interlocks from
[nbtevo-diag](https://github.com/FreZZZeR/nbtevo-diag) and the
[standalone native prototype](https://github.com/FreZZZeR/nbtevo-id6-apps)
into the existing ID6 Apps HMI, worker lifecycle and diagnostic lease.
Upstream's existing DSC_25 support is retained. No second transport, HMI command
channel or gateway lock is introduced.

**Experimental source with a limited parked ENET check; no N57 app installation
or HMI validation has been performed.** Bundled ZIPs remain upstream v0.7.4 and
do not contain this work. This is not a claim that every N57 DDE or head-unit
firmware is compatible. See the [captured results](#parked-enet-check-2026-11-21).

## DDE identity must be verified first

The checked N57 returned `62 F1 50 0F 1F 70`. This is one observed identity,
not an automatic compatibility entry. The test index `010203` is synthetic
and must never be used as a compatibility entry. Before enabling the profile,
independently identify the DDE as N57 using ISTA or equivalent factory diagnostic
information and record its actual
SGBD index. Do not infer engine identity from a plausible RPM or temperature.

The opt-in setting is `/var/opt/hmi/data/ID5/n57-sgbd.txt`: one nonzero,
six-digit hexadecimal SGBD index, with optional whitespace. Creating this file
on a head unit is an installation action requiring the owner's authorization.
With **Engine profile → Diesel** selected, BoostDeck passes the setting to its
collector; xDrive reads the same file. A missing file preserves the generic
upstream profile. An invalid existing file prevents the worker from starting.
For local development workers also accept `--n57-sgbd XXXXXX`.

Every N57 polling batch and every N57 xDrive safety check reads the actual DDE
index and requires an exact match. A mismatch leaves values blank or blocks
the mode change. This profile requires HSFZ; it does not fall back to MOST or
OBD mode 01. The existing gateway lease covers the complete dynamic-DID
transaction and releases the TCP connection before yielding to another app.

## Catalog and gauges

`native/src/n57_signals.def` contains all 22 `N57_DYNAMIC` definitions from
nbtevo-diag, derived from factory ISTA `d73n57*.prg` measured-value tables.
Only definitions are included; no factory binaries or private captures are
redistributed. The originating catalog is Apache-2.0; its license and notice
are in `source/third_party/nbtevo-diag/`.

Regenerate or compare against a local checkout of nbtevo-diag:

```sh
python3 source/tools/gen_n57.py --catalog /path/to/nbtevo-diag/nbtevo_diag/signals.py
python3 source/tools/gen_n57.py --catalog /path/to/nbtevo-diag/nbtevo_diag/signals.py --check
```

BoostDeck keeps the existing channel IDs and adds eight diesel selectors.
Under **OPTIONS → Engine profile → Diesel / N57**, select the profile, then
use **Configure gauges → Gauge 1…9** to choose a reading for any tile. A valid
DDE identity pin is still required for live N57 data; the generic Diesel
profile cannot supply these extra channels. Existing layouts are preserved.

| Selector | Source / conversion |
| --- | --- |
| Boost | DDE 4841 absolute pressure minus 4CF0 ambient pressure, hPa → psi |
| Intake air | DDE 4846, °C |
| Rail pressure | DDE 4746, raw × 0.045777 bar |
| Coolant | DDE 461B, °C |
| Oil temperature | DDE 4517, °C |
| Voltage | DDE 5242, V |
| RPM | DDE 5955, raw / 2 |
| Speed | DDE 4C14, raw × 2289 / 500000 km/h |
| MAP / barometric pressure | DDE 4841 / 4CF0, hPa → kPa |
| Air flow | DDE 47DC, kg/h → g/s |
| Ambient temperature | DDE 50A6, °C |
| Transmission temperature | Existing upstream EGS DA12 decode |
| DPF soot | DDE 44BE, raw × 0.015259 g |
| DPF pressure | DDE 44F8, raw × 0.045777 − 1000 hPa |
| DPF regen dist. | DDE 44BF, four-byte distance since regeneration in metres |
| EGT pre-DPF / EGT pre-cat | DDE 44EF / 44F2, raw × 0.031281 − 50 °C |
| AdBlue level | DDE 5306, raw × 0.001526 % |
| DDE torque | DDE 48A5, raw × 0.114443 − 2500 Nm |
| Power (calc.) | DDE torque × DDE RPM × 2π / 60000 kW |

Each DDE value clears F303 (`2C 03`), defines one measured value (`2C 01`),
then reads it (`22 F303`). An undefined-slot NRC 31 on clear is tolerated;
other failures, wrong widths, appended stale bytes and implausible values are
rejected. Boost requires both pressure readings. Unsupported gasoline fields
(including AFR, timing and oil pressure) remain blank. Diesel rail pressure
uses a 2500-bar gauge scale. Display units and upstream freshness limits apply.

Metric display uses g, hPa, km, °C, %, Nm and kW. Imperial display uses g, psi,
mi, °F, %, lb-ft and mechanical hp. **Power is an estimate from DDE-reported
engine torque, not a dyno or wheel-power measurement.** Each power sample reads
torque and RPM together under one lease, even when their own tiles are not
selected. If either read fails or is implausible, power is blank. Its age starts
before the pair, so a slow second read cannot make old torque appear fresh.
Torque and power expire after 2.5 s; the extra diesel sensors after 3.5 s.
Polling resumes at the next selector after yielding the gateway, so frequently
due channels cannot repeatedly displace the later DPF/EGT/power reads. Valid
samples keep their original age while waiting for the lease; they are not
refreshed by reconnecting.

New selectors are appended as IDs 31–38; persisted byte-sized assignments and
the original 0–30 IDs are unchanged. BoostDeck's local UDP format is now NBG8
with 39 values and a 64-bit validity/selection mask. The new HMI still accepts
NBG2–NBG7 frames, leaving absent diesel channels blank. An older HMI does not
understand NBG8: update its native library and collector together with the
regenerated `plugin/BoostDeck.xml`. The nine tiles and their image IDs are
unchanged, so their existing image archive is reused.

Regenerate the selector layout with `make -C source/native boostdeck-layout`.
The XML tests check all nine selection pages, action IDs, generation parity
and image availability in the upstream archive.

Injection quantity, charge-air/target-boost and fuel-volume selectors remain
catalog-only.

## ShiftDeck, LaunchDeck and HUD Gauges

All three now use the same independently verified `n57-sgbd.txt` pin without
needing a separate profile selection in each app. No pin preserves upstream's
OBD path. An invalid or unreadable existing setting blocks data collection;
an identity mismatch produces unavailable data. There is no N57
fallback to mode 01 or the MOST diagnostic tunnel. HUD rendering still uses
its original MOST HUDTerminal connection.

ShiftDeck and LaunchDeck share `shift-deck-qnx`. N57 reads use DDE 5955 for RPM
and 4C14 for speed through clear/define/read F303. LaunchDeck's `--speed-only`
path queries no RPM. Local development also accepts `--n57-sgbd XXXXXX`. The
N57 poll interval is at least 100 ms; each sample retains the beginning of its
read sequence as its timestamp. Slow replies cannot make delayed readings
look new. Parent-process shutdown, the shared gateway lease, and the 750 ms
HMI freshness limit remain in place.

The worker preserves fractional speed in thousandths of km/h in a versioned
24-byte DDE1 IPC packet. Both apps also accept upstream's 16-byte integer-km/h
packet. The new packet is checked for its 64-bit signature and plausibility;
its signature occupies the old timestamp position so an old HMI rejects it
rather than interpreting fractional speed as whole km/h. Update the worker
and both HMI libraries together. The LaunchDeck timer now
interpolates fractional speed through all four measurement modes; even the
smallest positive DDE speed cannot arm a standing start. Missing data or a
profile change aborts an active measurement. Historical result files keep
their existing format. Hundredths on screen are display resolution, not a
claim of measurement accuracy; ECU sampling and diagnostic latency still
limit the result.

ShiftDeck adds selectable **3500 / 4000 / 4500 RPM** thresholds, preserving the
old 5800–6700 options and action IDs. Its N57 default is 4000, stored separately
in `ShiftDeck.n57.prefs`; gasoline preferences remain in `ShiftDeck.prefs`.
These are user-selected warning thresholds, not a verified N57 rev limiter or
an optimum shift recommendation. The original 0–8000 display scale is retained.
The new targets require the regenerated XML and six extra images. Preserve
the shipped smooth assets when regenerating:

```sh
python3 source/native/tools/extend_shift_n57.py \
  --images /private/original/ShiftDeck_ALL_Images.zip \
  --images-out /private/candidate/ShiftDeck_ALL_Images.zip
```

HUD Gauges reads RPM from 5955 and boost from 4841 minus 4CF0 (hPa converted to
PSI). Both pressure reads must succeed; unavailable pressure is shown as `--`.
The N57 parked check uses exact zero DDE speed and the verified EGS selector
and status described below; fractional motion blocks it. RPM and pressure ages
include their diagnostic read time. The original 1100 ms RPM and 1200 ms boost
freshness limits apply.
The 0–8000 tach scale remains, but the gasoline 6700 RPM thick redline band is
suppressed for N57 rather than presented as a diesel limit. Factory navigation
ownership, the unique expected HUDTerminal node, handle allowlist and cleanup
are unchanged. Engine support does not establish cluster/firmware compatibility.

## xDrive interlocks

For DSC_25 `0F1860`, retain LMV `0F1480`, confirmed Park, engine running and
exact zero speed for both RWD and AWD. With an N57 pin, both xDrive and HUD's
parked reader require EGS identity `0F14B0`, selector `4306 = 08` (P), and
`DA27 = 00 01 00 00 00 00/01` (display P, centered lever, valid released/pressed
P button). Unknown EGS identities, other positions, invalid status and wrong
reply lengths block the operation. Factory GKE tables identify `DA2E` as
actual gear; the observed `00 01` in P is not a selector position. The separate
upstream reference profile is unchanged and is not used for pinned N57 Park.

N57 RPM and speed come from DDE 5955 and 4C14, not mode 01. Even a fractional
positive speed blocks switching. Existing DSC allowlists, LMV qualifiers,
confirmation flow, refusal handling and independent mode readback remain.

Every xDrive mode change additionally requires owner VIN consent. Provide the
17-character VIN locally in `/var/opt/hmi/data/ID5/xdrive-owner-vin.txt`, a regular
file owned by the worker's UID with mode `0600`; never commit it. The worker
requires a matching DDE `22 F1 90` response before proceeding. `NBTEVO_OWN_VIN`
can supply the same value to a locally launched worker; the HMI sanitizes its
child environment, so use the file for HMI operation. Missing, invalid or
mismatched consent blocks all writes. Read-only status needs no consent.
No force, waiver or automatic retry is added.

## Parked ENET check (2026-11-21)

Native host builds connected directly to the diagnostic gateway with the car
in P and the engine idling. The owner independently reported about 657–700 RPM
on the factory tachometer. DDE identity was `0F1F70`, EGS identity `0F14B0`, and
the head-unit firmware read was `NBTevo_N18032I`. These checks exercised native
diagnostic code from the computer, not apps running on the head unit.

| Check | Result and limit |
| --- | --- |
| ShiftDeck reader | DDE RPM 681, 676, 678; speed 0.0 km/h; valid DDE1 packets. Idle RPM agrees with the owner's approximate reference; higher RPM and moving speed remain unverified. |
| LaunchDeck speed-only reader | Speed 0.0 km/h; RPM omitted as intended. No launch or acceleration run. |
| HUD reader with Park required | Accepted P, 682 RPM and available pressure pair (about −5.2 psi). Renderer was not invoked; pressure accuracy was not independently compared. |
| AdBlue 5306 | Definition `2C 01 F3 03 53 06 01 02` rejected with `7F 2C 31`. Unavailable on the tested configuration; the existing decoder leaves it blank, without substituting zero or hiding other gauges. This response alone does not diagnose the reason. |
| EGT pre-DPF 44EF | Received about 142.7 °C; needs a trusted reference comparison. |
| EGT pre-cat 44F2 | Raw `06 3D` decoded to about 0 °C on a warm engine. Treat as an unconfirmed candidate, not a valid exhaust-temperature measurement. Do not select it for use until independently verified. |
| DPF / torque / calculated power | Received about 60.0 g soot, 0 hPa differential pressure, 0 m since regeneration, 22.55 Nm and 1.45 kW at idle. These are candidate decodes, not independently validated measurements or a diagnosis of the DPF. |

Minimal Park evidence (ECU `18`), with the owner confirming P:

```text
22 F1 50 -> 62 F1 50 0F 14 B0
22 43 06 -> 62 43 06 08
22 DA 27 -> 62 DA 27 00 01 00 00 00 00
22 DA 2E -> 62 DA 2E 00 01
```

The selector interpretation also matches the factory GKE `POS_PRND` and
`RES_0xDA27` tables. Only the observed EGS identity is enabled for N57 Park;
other EGS variants need their own evidence before extending this check.

Temporary F303 definitions were explicitly authorized and the final
`2C 03 F3 03 -> 6C 03 F3 03` cleanup succeeded. Diagnostic connections were
closed. No app or pin file was installed, no firmware/coding or xDrive mode
was changed, and no HUD overlay was drawn. Private captures and factory PRG
files are excluded from the public source.

## Local checks and remaining validation

```sh
make -C source/native test
```

Tests use synthetic identities and a loopback HSFZ model. They cover factory
scales, 32-bit distance, F303 append rejection, identity mismatch, fractional
motion, engine off, owner mismatch, ECU refusal, captured Park replies,
unknown EGS identities, invalid/contradictory selector status and reply lengths,
AdBlue definition NRC 31, power dependencies, 64-bit
masks, packet bounds, older wire formats, display units and blank gasoline
channels.
Passing these tests establishes local behavior, not vehicle compatibility.

The port is checked with QNX ARMv7 GCC 4.9.4, including the native workers and
HMI libraries. The private framework link inputs match the committed reference
hashes. HUD needs the compatible licensed HUDTerminal API described in
[BUILD.md](BUILD.md#build-hud-gauges); no NBT-AAD source or private frameworks
are redistributed here. The prescribed GCC 4.4.2 release build and complete
release package assembly have not been run.

Before any installation or command test, obtain the owner's authorization and
follow the normal firmware/framework checks. Independently compare the remaining
raw N57 readings with ISTA, check visible HMI behavior and freshness, and
verify command interlocks while parked. Real DSC/LMV actuation and readback
remain unverified for this port.
