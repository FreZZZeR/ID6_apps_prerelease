# Experimental N57 migration

This fork brings the factory-derived N57 catalog and xDrive interlocks from
[nbtevo-diag](https://github.com/FreZZZeR/nbtevo-diag) and the
[standalone native prototype](https://github.com/FreZZZeR/nbtevo-id6-apps)
into the existing ID6 Apps HMI, worker lifecycle and diagnostic lease.
Upstream's existing DSC_25 support is retained. No second transport, HMI command
channel or gateway lock is introduced.

**Source only; no car validation or installation has been performed.** Bundled
ZIPs remain upstream v0.7.4 and do not contain this work. This is not a claim
that every N57 DDE or head-unit firmware is compatible.

## DDE identity must be verified first

An actual N57 `22 F1 50` SGBD index has not yet been captured for this port.
The test index `010203` is synthetic and must never be used as a compatibility
entry. Before enabling the profile, independently identify the DDE as N57
using ISTA or equivalent factory diagnostic information and record its actual
SGBD index. Do not infer engine identity from a plausible RPM or temperature.

The opt-in setting is `/var/opt/hmi/data/ID5/n57-sgbd.txt`: one nonzero,
six-digit hexadecimal SGBD index, with optional whitespace. Creating this file
on a head unit is an installation action requiring the owner's authorization.
With **Engine profile → Diesel** selected, BoostDeck passes the setting to its
collector; xDrive reads the same file. A missing file preserves the generic
upstream profile. An invalid existing file prevents the worker from starting.
For local development workers also accept `--n57-sgbd XXXXXX`.

Every N57 polling batch and every N57 xDrive safety check reads the actual DDE
index and requires an exact match. A mismatch leaves values blank or blocks
the mode change. This profile requires HSFZ; it does not fall back to MOST or
OBD mode 01. The existing gateway lease covers the complete dynamic-DID
transaction and releases the TCP connection before yielding to another app.

## Catalog and gauges

`native/src/n57_signals.def` contains all 22 `N57_DYNAMIC` definitions from
nbtevo-diag, derived from factory ISTA `d73n57*.prg` measured-value tables.
Only definitions are included; no factory binaries or private captures are
redistributed. The originating catalog is Apache-2.0; its license and notice
are in `source/third_party/nbtevo-diag/`.

Regenerate or compare against a local checkout of nbtevo-diag:

```sh
python3 source/tools/gen_n57.py --catalog /path/to/nbtevo-diag/nbtevo_diag/signals.py
python3 source/tools/gen_n57.py --catalog /path/to/nbtevo-diag/nbtevo_diag/signals.py --check
```

BoostDeck fills only existing slots with matching meanings and units:

| Selector | Source / conversion |
| --- | --- |
| Boost | DDE 4841 absolute pressure minus 4CF0 ambient pressure, hPa → psi |
| Intake air | DDE 4846, °C |
| Rail pressure | DDE 4746, raw × 0.045777 bar |
| Coolant | DDE 461B, °C |
| Oil temperature | DDE 4517, °C |
| Voltage | DDE 5242, V |
| RPM | DDE 5955, raw / 2 |
| Speed | DDE 4C14, raw × 2289 / 500000 km/h |
| MAP / barometric pressure | DDE 4841 / 4CF0, hPa → kPa |
| Air flow | DDE 47DC, kg/h → g/s |
| Ambient temperature | DDE 50A6, °C |
| Transmission temperature | Existing upstream EGS DA12 decode |

Each DDE value clears F303 (`2C 03`), defines one measured value (`2C 01`),
then reads it (`22 F303`). An undefined-slot NRC 31 on clear is tolerated;
other failures, wrong widths, appended stale bytes and implausible values are
rejected. Boost requires both pressure readings. Unsupported gasoline fields
(including AFR, timing and oil pressure) remain blank. Diesel rail pressure
uses a 2500-bar gauge scale. Display units and upstream freshness limits apply.

The catalog also carries injection quantity, torque, exhaust temperatures,
DPF data, regeneration distance, AdBlue and fuel volume. Dedicated selectors
for these, computed power/torque displays and N57 calibration of ShiftDeck,
LaunchDeck and HUD Gauges have **not** been ported. Do not treat the existing
gasoline performance apps as N57-calibrated. New layout/model IDs and protocol
extensions should be a separate change with regenerated resources.

## xDrive interlocks

For DSC_25 `0F1860`, retain LMV `0F1480`, confirmed Park (`DA2E = 00 06`),
engine running and exact zero speed for both RWD and AWD. With an N57 pin,
RPM and speed come from DDE 5955 and 4C14, not mode 01. Even a fractional
positive speed blocks switching. Existing DSC allowlists, LMV qualifiers,
confirmation flow, refusal handling and independent mode readback remain.

Every xDrive mode change additionally requires owner VIN consent. Provide the
17-character VIN locally in `/var/opt/hmi/data/ID5/xdrive-owner-vin.txt`, a regular
file owned by the worker's UID with mode `0600`; never commit it. The worker
requires a matching DDE `22 F1 90` response before proceeding. `NBTEVO_OWN_VIN`
can supply the same value to a locally launched worker; the HMI sanitizes its
child environment, so use the file for HMI operation. Missing, invalid or
mismatched consent blocks all writes. Read-only status needs no consent.
No force, waiver or automatic retry is added.

## Local checks and remaining validation

```sh
make -C source/native test
```

Tests use synthetic identities and a loopback HSFZ model. They cover factory
scales, 32-bit values, F303 append rejection, identity mismatch, fractional
motion, engine off, owner mismatch, ECU refusal and blank gasoline channels.
Passing these tests establishes local behavior, not vehicle compatibility.

The initial port also cross-builds the two changed workers and BoostDeck for
QNX ARMv7 with GCC 4.9.4. BoostDeck's BMW framework imports are unchanged, and
the private link inputs match the committed reference hashes. The prescribed
GCC 4.4.2 release build and complete package assembly have not been run.

Before any installation or command test, obtain the owner's authorization and
follow the normal firmware/framework checks. Independently compare selected
raw N57 readings with ISTA, check visible HMI behavior and freshness, and
verify command interlocks while parked. Real DSC/LMV actuation and readback
remain unverified for this port.
