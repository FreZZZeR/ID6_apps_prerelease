# Experimental N57 support

This branch adds an identity-pinned N57 DDE profile and PowerDeck to the existing
ID6 Apps HMI and diagnostic workers. The current N57 bundle has seven apps: five
data apps (BoostDeck, ShiftDeck, LaunchDeck, PowerDeck and Engine Fault Codes),
plus optional xDrive Control and HUD Gauges. Basic diagnostic fields remain
selectable in BoostDeck; the separate BaseDiagnostik app is no longer shipped.
Existing upstream release
ZIPs, desktop installers and catalogue packages do **not** contain these source
changes. Build and verify a candidate from the intended source revision before
proposing an installation; this document is not an installation authorization.

The [data-availability matrix](N57-DATA.md) separates implemented channels, live
functional observations and measurements that still need independent calibration.
Use it with the [installation/rollback guide](INSTALL-N57.ru.md),
[transport notes](MOST.md) and [current update notes](N57-UPDATE.ru.md).

## Validation scope

An earlier N57 deployment received fresh data in BoostDeck, ShiftDeck, LaunchDeck,
PowerDeck and the former BaseDiagnostik app, and completed an Engine Fault Codes
read with ENET fully removed from OBD. This historical six-app observation predates
the removal of BaseDiagnostik; it is not a count of the current data apps.
BoostDeck additionally has runtime evidence of an
HSFZ-to-MOST transition in the same worker process. These were parked functional
checks; they do not establish every channel's scale or engineering accuracy.
ShiftDeck received data but intermittently showed RPM followed by dashes.

The current source includes further right-padding, grouped RPM/speed freshness
and PowerDeck preview/recording changes. **Those follow-up changes are offline
work and have not been checked on the vehicle.** A new vehicle/head-unit session
starting without ENET, concurrent physical AAD/HUD operation, N57 HUD rendering
and xDrive mode switching are not claimed as verified. A working engine gauge is
not evidence that a drivetrain command or HUD overlay is compatible.

## Selecting the N57 profile

BoostDeck retains two engine-profile choices: **Gasoline** and **Diesel**.
Diesel without an N57 pin uses the generic diesel/OBD path. Diesel with a valid
shared N57 pin selects the DDE/F303 path and labels it N57; this is not a third
independent engine-profile setting. The pinned path never substitutes mode-01
or gasoline readings for missing DDE data.

Before enabling it, independently identify the engine and DDE using factory
information or an equivalent trusted source. One observed DDE identity is
`0F1F70`; it is not an automatic compatibility entry for all N57 variants.
Record the verified six-digit SGBD index in the head unit's shared
`/var/opt/hmi/data/ID5/n57-sgbd.txt`. Creating or changing that file is part of an
authorized installation. The synthetic test index `010203` is not a vehicle
profile. An invalid existing setting or a mismatched DDE leaves data unavailable
and blocks relevant operations.

ShiftDeck and LaunchDeck use the shared N57 setting automatically; without it
they preserve the upstream OBD path. PowerDeck is N57-only
and requires a valid setting before it starts a collector. HUD uses the same
setting for its N57 reader, with the separate parked/ownership checks below.

## Channels and source availability

The [22 decoder definitions](../native/src/common/n57_signals.def) come from the
Apache-2.0 [nbtevo-diag catalogue](https://github.com/FreZZZeR/nbtevo-diag).
The [shared gauge map](../native/src/common/n57_gauges.def) defines the 22 current
dashboard slots; [UI availability](../native/src/common/n57_gauge_support.h) and
the [collector](../native/src/workers/boost_deck_worker.c) use that same map.
Only derived definitions and implementation code are included. Factory binaries,
proprietary PRG files and personal captures are not redistributed. Preserve the
[licence](../third_party/nbtevo-diag/LICENSE) and
[NOTICE](../third_party/nbtevo-diag/NOTICE).

To regenerate or check the decoder table against an authorized local catalogue,
run from the repository root, replacing `CATALOG_FILE` with that catalogue:

```sh
python3 source/tools/gen_n57.py --catalog CATALOG_FILE
python3 source/tools/gen_n57.py --catalog CATALOG_FILE --check
```

BoostDeck's pinned N57 view hides choices without a connected DDE implementation
and excludes them from polling. Existing custom assignments are retained, with
unsupported tiles hidden. The default N57 layout uses a separately labelled DDE
torque tile instead of the unimplemented Engine load tile. This does not turn
Nm into a load percentage. DID `464C` remains a metadata candidate requiring
service/layout/scale/meaning verification; no new load request is introduced.

Use **Configure gauges** to choose a supported value. **Hide emissions gauges**
hides AdBlue and DPF selectors and polling; **Show emissions gauges** restores
the stock view and saved assignments. EGT remains separately selectable. There
is no EGR gauge to hide. These settings change the application, not the vehicle.
See [units, unsupported fields and calibration limits](N57-DATA.md).

## Dynamic reads and MOST

N57 measurements use a temporary F303 diagnostic definition: clear the slot,
define the requested measured value or supported group, then read F303. Every
polling batch verifies the DDE identity; response echoes, exact lengths, decoder
bounds and freshness remain checked. F303 is shared ECU diagnostic state, so
other diagnostic clients must be closed. The common diagnostic lease covers
identity and each complete transaction/group, including derived pressure or
power pairs. No flashing or coding is performed by the telemetry path.

The new ShiftDeck path groups DDE `5955` RPM and `4C14` fractional speed into one
F303 definition/read with exactly four data bytes. LaunchDeck remains speed-only.
The timestamp starts at the actual measured-value read, before waiting for the
reply; identity and clear/define preparation do not date a measurement.
Diagnostic contention is not published as a new empty sample. Invalid, refused
or stale data remain unavailable; the 750 ms drive-display freshness limit is
not increased. This grouped-read/freshness change needs a new vehicle retest.

The existing versioned drive packet preserves fractional km/h; both HMI apps
retain support for the legacy upstream frame. Fractional movement must never
round down into a stationary safety decision. Acceleration timers retain their
own validity checks; their 0.01 s display resolution is not a precision claim.

Pinned N57 telemetry can switch from HSFZ to MOST after repeated transport
failures, including loss of a previously working HSFZ connection. ECU refusals,
identity mismatches and malformed values do not authorize a fallback that
bypasses those checks. Once on MOST, a worker remains there until it exits.
The current tunnel routes DDE/DME requests; EGS temperature remains unavailable
on that route. This is an implementation limitation, not a general limitation
of MOST. [Transport selection, ownership and evidence](MOST.md).

## Dashboard behaviour

The common layout uses RHMI design coordinates for the active display. Current
follow-up artwork leaves 24 logical units of right padding (about 21 panel pixels
on a 1280-pixel display). Libraries, manifests, XML and artwork must be updated
as a matching set. The new padding is not yet vehicle-validated.

LaunchDeck, ShiftDeck and BoostDeck collect only while their page
is shown and focused. PowerDeck collects in its focused live view; only an
explicit recording permits collection in a visible unfocused preview or native
OPTIONS. MENU and Saved review stop collection and end/save an active recording.
Ordinary preview without recording does not start a worker. Missing/malformed
Map activity is fail-closed, and queued callbacks must not restart a hidden app.
This PowerDeck follow-up behaviour is offline-only pending vehicle validation.

ShiftDeck's N57 scale is 0–6000 RPM. **OPTIONS → N57 shift window** sets a lower
warning and an upper stronger signal, initially 4600–4800 RPM. These are
user-selected visual thresholds, not a rev limiter, gearbox command or verified
optimum shift recommendation. Gasoline keeps its original profile and threshold.

PowerDeck shows DDE-reported torque and calculated power, with live and saved
curves. It accepts fresh coherent RPM/Nm/kW triples; it does not infer maximum
power from an idle/partial-load run. The last CSV is replaced atomically only
by a successful save. Empty measurements report **No data to save**; actual save
failures remain distinct. Start in Saved review is ignored; return to a live
view and explicitly start the next measurement. [Power and data limits](N57-DATA.md#torque-power-and-measurement-limits).

For basic diagnostics, assign DDE supply voltage, fuel volume in litres, coolant
or oil temperature to BoostDeck tiles through **Configure gauges**. These shared
channels remain implemented after removing the standalone basic-diagnostics app.
State of charge, CBS/brake wear and tyre pressures have no implemented source;
voltage is not converted into a charge percentage.

## HUD and projection ownership

HUD Gauges is optional and starts with `hud-enabled = 0`. Its checkbox is session-only:
opening the menu or restarting HMI does not auto-start rendering. N57 diagnostics do not
establish cluster compatibility. Before any overlay test, verify the factory
HUDTerminal node, handles, firmware and navigation ownership rules. The parked
reader requires exact zero DDE speed and the verified EGS Park responses.

The renderer consumes an active dashboard's published telemetry rather than
starting a second diagnostic poller. Its independent sampler and parked check
remain HSFZ-only. Without a usable RPM/boost source it leaves the overlay blank.
Its N57 tach treatment suppresses the gasoline redline emphasis; that is not a
validated diesel rev-limit indication.

Installed NBT-AAD/CarPlay HUD support or a projection marker blocks this overlay,
even if projection is stopped. N57 engine diagnostics may still use their separate
MOST service; that code policy does not establish simultaneous physical AAD/HUD
compatibility. Never stop projection or clear foreign HUD handles to force this
overlay. Preserve the licensed NBT-AAD code's PolyForm Noncommercial terms and
Required Notice; see [HUD build requirements](BUILD.md#build-hud-gauges).

## xDrive interlocks

Pinned N57 mode changes remain HSFZ-only and restricted to DSC_25 `0F1860` with
LMV `0F1480`. Both RWD and AWD require a running engine, exact zero DDE speed,
DDE identity match and EGS `0F14B0` Park verification: selector `4306 = 08` plus
valid `DA27` display/lever/button status. `DA2E` is actual gear, not a replacement
Park selector. Unknown modules, inconsistent replies or fractional movement block
the operation. No fallback to a generic/G-series safety profile is allowed for a
pinned N57 command.

A mode change additionally requires the owner's own 17-character VIN in
`/var/opt/hmi/data/ID5/xdrive-owner-vin.txt`, a regular file owned by the worker's
UID with mode `0600`, and a matching DDE VIN response. Keep its value private and
out of commits/history. `NBTEVO_OWN_VIN` is available to a local worker, while the
HMI uses the file because it sanitizes child environment variables. Missing,
invalid or mismatched consent blocks writes; read-only status needs no owner
file. Do not add a force/waiver or an automatic command retry.

A drivetrain test is a separate owner-authorized parked operation with independent
mode readback and a planned return to the intended mode. Engine telemetry, menu
installation and host tests do not validate physical switching.
