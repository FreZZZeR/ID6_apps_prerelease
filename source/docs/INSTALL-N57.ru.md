# ID6 Apps N57: установка локально собранного кандидата

Эта инструкция относится к согласованному комплекту из исходников N57.
Публичные ZIP, desktop installer и catalogue-пакеты upstream этих доработок не
содержат. Здесь не объявляется новый опубликованный установочный архив.
У подготовленного кандидата должны быть проверяемые исходная ревизия,
компилятор, состав и результаты проверок в `BUILD-INFO.json`.

Предыдущая N57-сборка функционально получала данные шести приложений без ENET,
включая прежнее BaseDiagnostik. В текущем наборе семь приложений, из них пять
читают данные; отдельного Base больше нет, его каналы доступны в BoostDeck.
Для BoostDeck отдельно подтверждён переход HSFZ → MOST в том же worker.
Текущие отступы, групповое чтение RPM/скорости и PowerDeck preview/recording
изменены офлайн и на машине ещё не проверены. Нет результатов нового старта без
ENET, одновременного активного AAD/HUD, физического HUD overlay и xDrive-switch.
Ограничения: [N57-DATA.md](N57-DATA.md), [N57-UPDATE.ru.md](N57-UPDATE.ru.md).

## Состав

| Папка | Приложение | Connector ID |
| --- | --- | --- |
| `core/BoostDeck` | Настраиваемые N57-гейджи, напряжение/топливо/ОЖ/масло, скрытие AdBlue/DPF | 100 |
| `core/ShiftDeck` | Обороты/скорость DDE, настраиваемое окно предупреждения 4600–4800 RPM | 104 |
| `core/LaunchDeck` | Дробная скорость DDE, замеры разгона | 120 |
| `core/EngineCodes` | Чтение и ручное удаление ошибок двигателя; описания N57 могут отсутствовать | 102 |
| `core/PowerDeck` | RPM, момент DDE, расчётная мощность; живые графики и сохранённые кривые Nm/kW/л.с. от RPM | 121 |
| `optional/XDriveControl` | DSC_25, N57-блокировки, проверка Park и владельца | 112 |
| `optional/HudTest` | HUD Gauges с оборотами и давлением DDE; при установке выключен | 107 |

MHD/Bootmod3/MG Flasher, BEAMer и Road Jet в этот набор не включены. Все папки приложений
самодостаточны: библиотека, коллектор, XML и необходимые изображения находятся
вместе. Нельзя смешивать новые библиотеки со старыми коллекторами или XML.

## 1. Проверить пакет на компьютере

Для подготовленного локального ZIP проверьте файл `.zip.sha256`. В примере замените `CANDIDATE` фактическим именем архива:

```sh
shasum -a 256 -c CANDIDATE.zip.sha256
```

Распакуйте ZIP, откройте его корневую папку и выполните:

```sh
shasum -a 256 -c SHA256SUMS
```

Все строки должны завершиться `OK`. Внутри каждой папки приложения есть ещё
свой `SHA256SUMS` для проверки файлов при переносе. В ZIP нет паролей, VIN,
библиотек BMW, активных настроек конкретной машины или скрипта автоматической
загрузки. Лицензии и обязательные уведомления находятся в `licenses/`.

## 2. Проверить автомобиль перед будущей установкой

Установку выполнять отдельно, с разрешения владельца, на стоящей машине в P
со стояночным тормозом. Подключить ENET, включить зажигание, обеспечить стабильное
питание и закрыть другие
диагностические программы. Этот документ не является указанием подключаться
или устанавливать пакет без такого разрешения.

В проекте сохранена reference-пара для `NBTevo_N18032I` и экрана 1280×480.
Она не заменяет проверки фактического кандидата:

| Библиотека HMI | SHA-256 |
| --- | --- |
| `libAppFramework.A.so` | `93f4c7ab7e59c0adf7923b9b491de06165ba9d97bbe7412292e7ddc418ca2123` |
| `libCoreFramework.A.so` | `64ba154c68c772f9ca779fc18507f5b34715be58ded4a198b8a62b90d16c3ee0` |

Сверить фактическую прошивку, обе библиотеки и разрешение по [матрице совместимости](COMPATIBILITY.md).
Другая пара требует отдельной проверки. Записать действительно использованный
компилятор; стандартный build script задаёт GCC 4.4.2, альтернативный toolchain
требует собственного подтверждения. Статическая проверка не заменяет загрузку
и проверку HMI; успешный прошлый кандидат не проверяет новый.

Адрес диагностического шлюза TCP 6801 и адрес SSH головного устройства — разные
адреса. Определить их заново: прошлые link-local адреса могут измениться.
Не подставлять адрес из прошлого сеанса или reference-настройки без проверки.

На split-node NBT EVO SSH может открываться на Jacinto (`uname -a`: `hu-jacinto`),
а HMI работает на `hu-omap`. Приложения и настройки нужны **на OMAP**:
`/var/opt/hmi/data/ID5/Plugins` и `/var/opt/hmi/data/ID5`.
Использовать подтверждённый SSH-доступ к OMAP либо его проверенный Qnet-путь
с Jacinto. Копирование в одноимённый локальный каталог Jacinto не устанавливает
приложения HMI. Команды просмотра HMI через Jacinto выполняются с
`on -f hu-omap ...`; точку монтирования Qnet нужно определить по самой голове.

## 3. Резервная копия и перенос

Если раньше было установлено BaseDiagnostik, новый архив сам его не удаляет.
Его удаление выбирается отдельно: сохранить папку/настройки в backup и только
затем убрать именно выбранное старое приложение. Совместимость владения со
старым Base-клиентом сохранена; зарезервированные порты не переиспользуются.

1. Проверить существующие папки Plugins и Connector ID из таблицы. Одна версия
   приложения и один владелец каждого ID; существующие CarPlay/AA и другие
   приложения не заменять.
2. Сохранить старые папки выбранных приложений и их права в отдельную резервную
   копию **вне Plugins**, например
   `/var/opt/hmi/data/ID5/PluginBackups/N57-YYYYMMDD-HHMM`.
   Скопировать резервную копию на компьютер.
3. Отдельно сохранить существующие `BoostDeck.signals`, `BoostDeck.prefs`,
   `ShiftDeck.prefs`, `ShiftDeck.n57.prefs`, `ShiftDeck.n57.window.prefs`, настройки/результаты LaunchDeck,
   `PowerDeck.last.csv`,
   `n57-sgbd.txt`, `gateway-ip.txt`, `xdrive-owner-vin.txt` и локальные настройки
   заменяемых приложений, если они есть. Файлы VIN хранить приватно.
4. Новые папки сначала загрузить в отдельный staging-каталог на OMAP вне Plugins.
   Для первого запуска выбрать основные приложения; HUD и xDrive добавлять
   отдельно по выбору владельца. Проверять BoostDeck первым.
5. Проверить каждый перенесённый файл по SHA-256: при отсутствии подходящей
   команды на QNX считать файлы обратно на компьютер и проверить локальный
   `SHA256SUMS`. Бинарники переносить без преобразования текста.
6. Выдать право исполнения новым коллекторам в каждой выбранной папке (`chmod 755`):
   `boostdeck-collector-qnx`, `shift-deck-qnx` в обеих папках ShiftDeck/LaunchDeck,
   `engine-codes-qnx`, а при выборе опций — `xdrive-control-qnx`, `hud-shape-qnx`.
   Библиотеки `lib*.so` и ресурсы должны читаться пользователем HMI.
7. После проверки переместить старые версии в резервный каталог, а новые целые
   папки — в Plugins под исходными именами из таблицы. Не оставлять backup-копии
   внутри Plugins. Не смешивать файлы разных версий.

## 4. Включить N57-профиль

Общая настройка на OMAP: `/var/opt/hmi/data/ID5/n57-sgbd.txt`.
Содержимое — ровно один шестизначный SGBD-индекс DDE с переводом строки.
Одна наблюдавшаяся N57-конфигурация имеет индекс `0F1F70`.
Пример в локальном комплекте `config/n57-sgbd.txt.example` содержит:

```text
0F1F70
```

Не копировать пример до независимого подтверждения N57 и точного индекса DDE.
Только затем создать файл с проверенным содержимым. `010203` —
тестовый индекс, для автомобиля он непригоден. Несовпадение индекса блокирует
данные/команды. В BoostDeck выбранный Diesel без pin использует общий diesel/OBD-путь;
при валидном pin — N57 DDE/F303. ShiftDeck/LaunchDeck без pin сохраняют upstream-путь;
N57-only PowerDeck без корректного pin не начинает опрос.

При необходимости записать **проверенный текущий IPv4 шлюза** в общий файл
`/var/opt/hmi/data/ID5/gateway-ip.txt`. Существующую рабочую настройку сохранить.
Неверный адрес SSH не подходит. Без файла приложения используют автоопределение.

BoostDeck выбирать **OPTIONS → Engine profile → Diesel / N57**.
Для конфигурации без AdBlue/DPF выбрать **Hide emissions gauges**; для штатного
N57 оставить **Show emissions gauges**. Выбор сохраняется, скрытые назначения
плиток восстанавливаются при обратном включении. EGR-канала в этом fork пока
нет. EGT выбирается отдельно: канал перед катализатором ещё не подтверждён.

ShiftDeck/LaunchDeck/HUD используют общий N57-файл автоматически.
Пороги ShiftDeck — пользовательские предупреждения, не рекомендация оборотов
переключения. Расчётная мощность — оценка по моменту DDE, не мощность на колёсах.
Доступность, единицы и границы проверки перечислены в [N57-DATA.md](N57-DATA.md).
Engine load не реализован: неподдержанные N57-выборы скрыты, а default-раскладка
использует отдельно подписанный момент DDE. Это не процент нагрузки.

Коллекторы и HUD из этого пакета обновлять одним согласованным набором:
служебные порты координации перенесены в `42970–42983`. Старые и новые workers
вместе не проверены. Описание владения MOST/HUD включено в архив как `docs/MOST.md`.

Для отдельной стояночной проверки автономности сначала сверить RPM и данные с
ENET, затем по команде владельца полностью извлечь кабель из OBD и проверить
те же приложения. Один подключённый конец кабеля не является проверкой полностью
отключённого ENET. Новый старт машины/головы и совместную работу с активными AAD/HUD
фиксировать отдельными согласованными этапами. Результат прошлой функциональной
проверки не заменяет эти проверки или независимую калибровку.

## 5. Опциональные xDrive и HUD

**xDrive.** Пакет не содержит разрешающего VIN-файла. При его отсутствии смена
режима заблокирована. Для отдельного будущего командного теста потребуется
`/var/opt/hmi/data/ID5/xdrive-owner-vin.txt`: собственный 17-символьный VIN,
обычный файл с правами `0600`, принадлежащий UID коллектора. VIN не писать в
публичные инструкции или историю команд. Приложение требует совпадения VIN DDE,
поддерживаемых DSC/LMV, EGS `0F14B0`, P по `4306` и `DA27`, нулевой скорости и
работающего двигателя для N57/DSC_25. Завершение переключения проверяется
независимым чтением режима. Наличие меню не подтверждает работу на машине.

**HUD.** Папка HudTest содержит безопасный `hud-enabled = 0`.
Галочка действует только в текущем сеансе iDrive: открытие меню и перезапуск HMI
не восстанавливают overlay автоматически; включение требует явного действия.
Нужна отдельная проверка MOST HUDTerminal, ожидаемого узла `0101`, навигации и
допустимых handles. Результат чтения P/RPM ещё не подтверждает совместимость
6WB/6WA с overlay. Сначала проверить основные приложения; включение галочки
HUD — отдельный тест владельца. Код на основе NBT-AAD имеет лицензию PolyForm
Noncommercial; её текст и Required Notice включены в пакет.

При установленном NBT-AAD или CarPlay HUD наш HUD Gauges блокируется и сообщает
причину: стрелки проекции имеют приоритет. Для N57-диагностики установка AAD сама по себе не запрещает MOST.
Сохранность активных стрелок/звука AAD ещё требует отдельной физической проверки. Самостоятельный
sampler HUD использует HSFZ; при активном dashboard второй опрос не запускается.

## 6. Первый запуск и откат

После проверки файлов и настроек согласовать с владельцем штатный перезапуск
iDrive способом, поддерживаемым данной головой. Прошивку и кодировку для установки этого
пакета менять не требуется.

Проверить появление выбранных меню, запуск/остановку коллекторов при входе и
выходе, отсутствие зависаний и конфликтов шлюза. В P на холостых сравнить RPM
со штатным тахометром, убедиться в нулевой скорости, проверить сохранение
профиля и скрытия показателей. Неподдерживаемые и устаревшие значения должны
показываться без данных. Первый запуск не включает замеры разгона, удаление
ошибок, смену xDrive или HUD-отрисовку.

Для отката выключить HUD через его меню, закрыть приложения, вернуть выбранные
папки из резервной копии, восстановить их прежние настройки и повторить
согласованный перезапуск. Старые версии BoostDeck не читают новый формат B3:
при возврате старой версии восстановить её `BoostDeck.signals` из backup.
Настройки чужих приложений и общие файлы, которые были до установки, сохранять.
Удаление xDrive-меню не восстанавливает режим привода; если режим менялся,
его возврат выполняется отдельно по процедуре для подтверждённого DSC.
